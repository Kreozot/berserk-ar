# План разработки Berserk AR

## Цель прототипа

Сделать мобильное приложение, которое видит расклад карт ККИ «Берсерк» через камеру, распознаёт отдельные карты, подсвечивает их поверх изображения и по нажатию открывает заранее сохранённое изображение распознанной карты на весь экран.

Первый прототип строится только на наборе **«Легенды Лаара» (19 карт)**. Это позволит проверить распознавание и UX на маленьком контролируемом датасете прежде, чем масштабировать решение на другие выпуски.

### 2. Выбор технического стека
Для первого прототипа выбрана конфигурация:
- Expo SDK 57 / React Native 0.86;
- `react-native-vision-camera`;
- `react-native-fast-opencv` для детекции и perspective correction;
- ORB feature matching для идентификации карт;
- обычный React Native overlay на первом этапе.

ORB и OpenCV рассматриваются как сменные адаптеры. Детали и границы архитектуры зафиксированы в `docs/adr/0001-card-recognition-architecture.md`.

### 6. Трекинг и плавный AR-overlay
- Не выполнять тяжёлое распознавание на каждом кадре.
- Между распознаваниями отслеживать уже найденные карты.
- Стабилизировать координаты рамок, чтобы они не дрожали.
- Корректно обрабатывать появление, перемещение и исчезновение карты.
- Добавить отдельные tracking IDs для нескольких физических копий одной карты.

### 7. Проверка прототипа
Проверить минимум следующие сценарии:
- одна карта;
- несколько карт одновременно;
- карты рядом и частично перекрываются;
- сильный наклон камеры;
- поворот карты;
- блики;
- слабое освещение;
- рука частично закрывает карту;
- похожие по цветам/композиции карты;
- прямоугольные объекты, которые не являются картами Berserk.

Для каждого сценария фиксировать точность распознавания, задержку и субъективную стабильность overlay.

### 8. Масштабирование
После успешного прототипа:
- добавить следующие выпуски;
- автоматизировать импорт изображений и метаданных;
- проверить, как алгоритм распознавания масштабируется с 19 до сотен/тысяч карт;
- при необходимости добавить другой `CardRecognizer` (например embeddings / ML retrieval) без изменения UI и camera pipeline.

## Принципы реализации
- Сначала минимальный работающий прототип, затем оптимизация.
- Computer vision отделён от UI через небольшой стабильный интерфейс.
- Каталог карт не должен быть жёстко зашит в алгоритм распознавания.
- Любой алгоритм распознавания должен уметь возвращать `unknown`.
- OpenCV/ORB-специфичные типы не выходят за границы инфраструктурных адаптеров.
- Измеряем производительность на реальном устройстве, а не только в симуляторе.
