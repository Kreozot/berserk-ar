# План разработки Berserk AR

## Цель прототипа

Сделать мобильное приложение, которое видит расклад карт ККИ «Берсерк» через камеру, распознаёт отдельные карты, подсвечивает их поверх изображения и по нажатию открывает заранее сохранённое изображение распознанной карты на весь экран.

Первый прототип строится только на наборе **«Легенды Лаара» (19 карт)**. Это позволит проверить распознавание и UX на маленьком контролируемом датасете прежде, чем масштабировать решение на другие выпуски.

## Этапы

### 1. Подготовка репозитория и датасета
- Зафиксировать цель и план проекта.
- Добавить изображения всех 19 карт «Легенды Лаара».
- Добавить машиночитаемый каталог карт с ID, названием и локальным путём к изображению.
- Зафиксировать источник изображений и статус прав на них.

### 2. Выбор технического стека
До начала реализации сравнить и выбрать решения для:
- камеры в React Native;
- обнаружения границ карт в кадре;
- идентификации конкретной карты;
- трекинга карты между кадрами;
- отрисовки интерактивного overlay;
- хранения/обновления каталога карт.

Выбранные решения оформить отдельным ADR/technical-design документом.

### 3. Camera MVP
- Открыть live camera preview.
- Получать кадры или frame processor callbacks.
- Отрисовывать поверх камеры тестовые интерактивные рамки.
- По нажатию на рамку открывать экран/модальное окно с изображением карты.

На этом этапе распознавание можно временно заменить mock-данными, чтобы отделить UI от computer vision.

### 4. Детекция карт
- Находить в кадре прямоугольные области, похожие на игровые карты.
- Корректировать перспективу (homography / perspective transform).
- Нормализовать найденную карту до фиксированного размера.
- Проверить работу при наклоне, разных расстояниях и частичном перекрытии.

### 5. Распознавание «Легенд Лаара»
- Реализовать выбранный алгоритм идентификации одной из 19 эталонных карт.
- Возвращать `cardId`, confidence и координаты четырёх углов.
- Добавить порог уверенности и состояние `unknown`, чтобы приложение не показывало неверную карту.

### 6. Трекинг и плавный AR-overlay
- Не выполнять тяжёлое распознавание на каждом кадре.
- Между распознаваниями отслеживать уже найденные карты.
- Стабилизировать координаты рамок, чтобы они не дрожали.
- Корректно обрабатывать появление, перемещение и исчезновение карты.

### 7. Проверка прототипа
Проверить минимум следующие сценарии:
- одна карта;
- несколько карт одновременно;
- карты рядом и частично перекрываются;
- сильный наклон камеры;
- поворот карты;
- блики;
- слабое освещение;
- рука частично закрывает карту;
- похожие по цветам/композиции карты.

Для каждого сценария фиксировать точность распознавания, задержку и субъективную стабильность overlay.

### 8. Масштабирование
После успешного прототипа:
- добавить следующие выпуски;
- автоматизировать импорт изображений и метаданных;
- проверить, как алгоритм распознавания масштабируется с 19 до сотен/тысяч карт;
- при необходимости перейти на другой способ идентификации (например embeddings / ML retrieval).

## Принципы реализации
- Сначала минимальный работающий прототип, затем оптимизация.
- Computer vision отделён от UI через небольшой стабильный интерфейс.
- Каталог карт не должен быть жёстко зашит в алгоритм распознавания.
- Любой алгоритм распознавания должен уметь возвращать `unknown`.
- Измеряем производительность на реальном Android-устройстве, а не только в симуляторе.
- Не привязываемся к конкретной CV/ML-библиотеке до сравнения вариантов.
